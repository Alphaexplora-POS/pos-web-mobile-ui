## Code Quality Principles
- **KISS** – Keep It Simple, Stupid. Use the simplest solution that works.
- **DRY** – Don't Repeat Yourself. Avoid duplicated logic.
- **YAGNI** – You Aren't Gonna Need It. Don't build for features not currently needed.
- **SOLID** – Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.
- **AHA** – Avoid Hasty Abstractions. Don't abstract until a pattern repeats.
- **POLA** – Principle of Least Astonishment. Code should behave as expected, no surprises.
- **SLAP** – Single Level of Abstraction Principle. Keep each function at one level of detail.
